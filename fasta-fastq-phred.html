FASTA, FASTQ & the Secret Code in Your DNA Files

By Aathma Merin Bejoy · August 6, 2026 · 6 min read

If you're stepping into bioinformatics for the first time, two file types will show up almost immediately: FASTA and FASTQ. They look cryptic at first — walls of A's, C's, G's, and T's, sprinkled with punctuation that seems random. But once you understand what each line is doing, they're genuinely simple. Let's walk through them together, no prior knowledge assumed.

FASTA: the plain and simple one

Think of FASTA as the "just the text, please" format. It stores a biological sequence — DNA, RNA, or protein — and almost nothing else.

A FASTA record is only two parts:

>my_first_sequence some optional description
GATTACAGATTACAGATTACAGATTACA

The first line always starts with a > (greater-than sign). That's the header — a name for the sequence, plus any description you feel like adding. Every line after it, until the next >, is the sequence itself.

That's the whole format. A FASTA file can hold one sequence or a million of them, each introduced by its own > header. It's perfect when all you care about is what the sequence is — for example, a reference genome you want to compare your data against.

But FASTA has a blind spot. When a DNA sequencing machine reads a real biological sample, it isn't equally sure about every letter. Some bases it reads crisply and confidently; others are a blurry guess. FASTA has no way to record that confidence. Every letter looks equally trustworthy, even when it isn't.

That's exactly the gap FASTQ fills.

FASTQ: FASTA's smarter cousin

FASTQ stores the same sequence letters, but adds a quality score for every single base — a note on how confident the machine was about each letter it read. This is the format that comes straight out of modern sequencers like Illumina, and it's where most real analysis begins.

The magic number to remember: a FASTQ record is always exactly four lines.

@read_001 instrument info here
GATTACAGATTACAGATTACAGATTACA
+
IIIIIIIIIIIIIII?5+!!!!!!!!!!

Here's what each line does:

  1. Line 1 — the ID. Starts with @. It's the name of the read, usually with machine details tacked on. (Note: @ here, > in FASTA — an easy way to tell the two files apart at a glance.)
  2. Line 2 — the sequence. The actual bases: A, C, G, T, and sometimes N (which means "I couldn't tell").
  3. Line 3 — the separator. Just a + sign, marking the boundary between the sequence and the quality scores.
  4. Line 4 — the quality string. One character per base, describing how confident the machine was about each letter above it.

The single most important rule of FASTQ: line 2 and line 4 must be the same length. Every base gets exactly one quality character sitting beneath it, like a caption under each letter.

The idea behind quality scores

So what does that weird string on line 4 actually mean? Each character is a compact way of writing a Phred quality score — a number that tells you how likely the base call is to be wrong.

The rule is simple once you see it: higher score = more confident. Scientists express it with this formula:

Q = −10 × log₁₀(Perror)

Don't let the log scare you. All it's really saying is: every time the error rate drops by 10×, the quality score goes up by 10. Here's the whole idea in a small table:

Quality (Q)Chance the base is wrongAccuracy
101 in 1090%
201 in 10099%
301 in 1,00099.9%
401 in 10,00099.99%

Q30 is the number you'll hear thrown around as "good quality." It means there's only a 1-in-1,000 chance that base is a mistake.

Phred+33: turning a number into a character

Now for the part that confuses almost every beginner. If quality scores are numbers like 30 and 40, why does line 4 look like IIIII?5+! instead of digits?

Because of that one strict rule: one character per base. If we wrote "30" that's two characters, and the alignment with the sequence would fall apart instantly. So we need a way to squeeze any score into a single character.

The trick is to borrow from ASCII, the standard table that gives every keyboard character a number. In ASCII, ! is 33, + is 43, 5 is 53, ? is 63, and I is 73. The recipe is beautifully simple:

character's ASCII number = quality score + 33

That "+ 33" is why the format is called Phred+33. Why add 33? Because the ASCII numbers below 33 are invisible control characters (spaces, tabs, line breaks) that would corrupt a text file. Adding 33 shifts every score up into the safe, printable zone, starting at !.

Let's decode a real example. Take this quality string:

I ? 5 + !

Subtract 33 from each character's ASCII value:

  • I → 73 − 33 = Q40 (superb)
  • ? → 63 − 33 = Q30 (great)
  • 5 → 53 − 33 = Q20 (okay)
  • + → 43 − 33 = Q10 (shaky)
  • ! → 33 − 33 = Q0 (basically a coin flip)

Watch out for one sneaky trap: that 5 means Q20, not the number five! It's an ASCII code that happens to look like a digit. This exact mix-up trips up nearly everyone at first, so now you're ahead of the game.

Notice the pattern in the decoded scores, too — they start high and fade to garbage. That's completely normal: sequencing reads tend to get less reliable toward their tail end, which is why quality often drops off near the finish.

Putting it all together

Here's the whole story in one breath. FASTA stores sequences and nothing else — clean and minimal. FASTQ adds a quality score for every base, packed into four tidy lines. And Phred+33 is the clever shorthand that shrinks each score into a single printable character by adding 33 and reading it off the ASCII table.

Master these three ideas and you've unlocked the front door of bioinformatics — because nearly every sequencing analysis, from quality checks to genome assembly, starts right here.

Happy sequencing! 🧬
